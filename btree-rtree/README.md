# B-treeとR-treeを可視化してみた

「なぜXYの複合インデックスでは足りないのか？」を、アニメーションで見せる5分発表用の HTML プレゼンテーションです。

## 起動方法

- `index.html` をブラウザ（Chrome / Edge / Safari の最新版）で開くだけで動きます。ビルドもサーバーも要りません。
- `F` キーか右上の ⛶ ボタンでフルスクリーンになります。
- 画面は 1920×1080 の 16:9 で描画し、ウィンドウサイズに合わせて拡大・縮小します（余白はレターボックス表示）。
- URL の `#番号` が現在のステップです（例: `index.html#12`）。リロードしても同じステップから再開できます。

## 操作方法

| 操作 | 動作 |
|---|---|
| → / Space / Enter / PageDown | 次のステップ |
| ← / Backspace / PageUp | 前のステップ |
| Home / End | 最初 / 最後のステップ |
| R | 現在のステップのアニメーションを再生し直す |
| F | フルスクリーン切り替え |
| 画面の右半分 / 左半分をクリック | 次 / 前 |
| 右下 › / 左下 ‹ ボタン | 次 / 前（背景クリックとは二重発火しません） |

- 進むとそのステップのアニメーションが自動再生されます。次のステップへは自動では進みません。
- 戻る・ジャンプでは、そのステップのアニメーション完了後の状態がすぐに表示されます。もう一度進めばアニメーションが再生されます。
- アニメーション中に操作したり連打したりしても、表示が崩れることはありません。

## 構成（全8シーン・25ステップ）

| # | シーン | ステップ数 |
|---|---|---|
| 1 | タイトル | 1 |
| 2 | XY座標をDBに格納（CREATE INDEX / SELECT） | 3 |
| 3 | B-treeの世界：2次元 → (x, y) 辞書順の1列 | 4 |
| 4 | B-treeで矩形検索（X範囲 → Y評価 → 件数） | 4 |
| 5 | R-treeの構造（葉 → 中間 → 上位の MBR） | 4 |
| 6 | R-treeで矩形検索（階層ごとの交差判定 → 点の検査 → 結果） | 5 |
| 7 | 左右に並べた比較 | 3 |
| 8 | まとめ | 1 |

## 使用技術

- 素の HTML / CSS / JavaScript と Canvas 2D。外部ライブラリなし、オフラインで動作。
- 2,000 点を毎フレーム描くため、SVG ではなく Canvas を使っています。

## 実装の概要

### 描画の考え方

画面は「ステップ番号 `k` と、そのステップに入ってからの経過時間 `t`」だけから毎フレーム描き直しています（`index.html` の `P()` / `vis()`）。
アニメーションの途中状態を変数に持たないので、どのステップへ移動しても表示は同じになります。
前に進むときは `t = 0` から、戻るときは `t = ∞`（完了状態）で描きます。

### データ（`model.js`）

- 固定シード（mulberry32）で 0〜100 の範囲に 2,000 点を生成します。75% が一様分布、25% が5つの緩やかなクラスタです。座標は小数1桁。
- 検索条件は `40 ≤ x ≤ 60 AND 40 ≤ y ≤ 60`。画面の件数はすべてこのデータから実際に計算した値です。

### B-tree (x, y)

- 葉レベルの論理的な並びとして、`(x, y, id)` の辞書順でソートした配列を使います。
- `x ≥ 40` と `x > 60` の位置を二分探索で求め、その間の連続区間を走査しながら y を評価します。Skip Scan などの最適化を使わない、典型的な範囲スキャンのモデルです。

### R-tree

- STR（Sort-Tile-Recursive）でバルクロードした実際の木です。1ノードの最大エントリ数は 9 で、ルート 1 → 上位 3 → 中間 25 → 葉 223 → 点 2,000 の階層になります。
- 各ノードは MBR・子ノード・配下の点を持ちます。MBR 同士が重なることもあります。
- 検索ではルートから再帰的にたどって MBR の交差を判定し、`{node, depth, hit}` のイベント列と、検査した点・結果を記録します。画面はこの記録をそのまま再生しています。

### 現在のデータでの数値

| | B-tree (x, y) | R-tree |
|---|---|---|
| 検索結果 | 56 件 | 56 件（集合として完全一致） |
| 調べた点エントリ | 389 件（x 範囲の走査） | 90 件（到達した葉ノード内の点） |

「調べた点」はインデックス上で検査した点エントリの数です。R-tree の MBR 判定（58 ノード）、ノード訪問数、I/O、実行時間は含みません。そのため性能を厳密に比べた数字としては扱わないでください。

数値は次のコマンドで確認できます。

```sh
node -e 'const m=require("./model.js").build(9);console.log(m.bres.scanned.length,m.bres.results.length,m.rres.examined.length,m.rres.results.length,m.resultsMatch)'
```

## 技術的な注意（発表で聞かれたとき用）

- Y 条件もインデックス上で評価されます（「Y はまったく使われない」わけではありません）。ただし先頭キー x が範囲条件なので、走査する範囲は x だけで決まります。
- B-tree でも、別々のインデックスの組み合わせ（Bitmap AND など）や、Z-order / Hilbert 曲線による座標の符号化を使えば空間検索はできます。DBMS によっては Skip Scan もあります。
- R-tree が常に B-tree より速いわけではありません。データの分布、選択率、更新の頻度、実装によって結果は変わります。
