## 2. 変数には何が入っている？（〜35秒）｜ステップ 4〜7

**ステップ 4**（`int a = 10`）

> 「答えの前に、まず変数の中身を見ます。int の a には、10 がそのまま入っています。」

→ **ステップ 5**（オブジェクトが現れる）

**見てほしいもの**：緑のカードと、右上の `#001`

> 「では Box はどうか。new Box で、まずオブジェクトが作られます。#001 は、このオブジェクトを区別するための名札です。説明用で、メモリアドレスではありません。」

→ **ステップ 6**（`#001` が a に入り、矢印が伸びる）

→ **ステップ 7**（原理①）

> 「どちらも変数には値が入っています。違うのは中身。値型はデータそのもの、参照型はオブジェクトへの参照です。これが 1 つ目のポイントです。」

## 3. 値渡しは「コピー」するだけ（〜55秒）｜ステップ 8〜13

**ステップ 8**（関数の枠と、空の箱 x）

→ **ステップ 10**（x が 20 に）

> 「関数の中で x を 20 にします。でも a は 10 のまま。別の箱ですからね。ここまでは直感どおりです。」

→ **ステップ 11**（下段：参照型で同じことをする）

→ **ステップ 13**（原理②の前半）

## 質問されそうなこと

- **「string も参照型なのに、関数の中で変えても呼び出し元が変わらないのは？」**：string は不変なので、`s = s + "x"` は新しいオブジェクトを作って変数 s に代入しています。シーン5と同じ形です。
- **「構造体はスタックに置かれるから、では？」**：置き場所ではなく「変数に何が入っているか」で説明できます。クラスのフィールドにある構造体はヒープに置かれますが、コピーされる動きは同じです。
- **「#001 はアドレス？」**：説明用の名前です。C# の参照は言語仕様上は中身の見えない値として扱われます。
- **「out や in は？」**：どちらも参照渡しの仲間です（out は関数側で必ず代入する、in は読み取り専用）。
