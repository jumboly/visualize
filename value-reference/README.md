# 値渡しなのに値が変わる？

値型・参照型と値渡し・参照渡しを可視化してみた ── 5分発表（ゆるトーク）用の HTML プレゼンテーションです。
4 パターンを暗記するのではなく、次の 3 つの原理から結果を導けるようになることを目指しています。

1. 変数には何が入っている？
2. コピーする？ 元の変数を操作する？
3. 変数を変える？ オブジェクトを変える？

## 起動方法

- `index.html` をブラウザ（Chrome / Edge / Safari の最新版）で開くだけで動きます。ビルドもサーバーも要りません。
- `F` キーか右上の ⛶ ボタンでフルスクリーンになります。
- 画面は 1920×1080 の 16:9 で描画し、ウィンドウサイズに合わせて拡大・縮小します（余白はレターボックス表示）。
- URL の `#番号` が現在のステップです（例: `index.html#12`）。リロードしても同じステップから再開できます。

## 操作方法

| 操作 | 動作 |
|---|---|
| → / Space / Enter / PageDown | 次のステップ |
| ← / Backspace / PageUp | 前のステップ |
| Home / End | 最初 / 最後のステップ |
| R | 現在のステップのアニメーションを再生し直す |
| F | フルスクリーン切り替え |
| 画面の右半分 / 左半分をクリック | 次 / 前 |
| 右下 › / 左下 ‹ ボタン | 次 / 前（背景クリックとは二重発火しません） |

- 進むとそのステップのアニメーションが自動再生されます。次のステップへは自動では進みません。
- 戻る・ジャンプでは、そのステップのアニメーション完了後の状態がすぐに表示されます。もう一度進めばアニメーションが再生されます。
- アニメーション中に操作したり連打したりしても、表示が崩れることはありません。

## 図の読み方

| 見た目 | 意味 |
|---|---|
| 青い実線の箱 | 変数。中に入っているのがその変数の値 |
| 白い数字 / `Value 10`（箱の中） | 値型のデータそのもの（int / struct） |
| 水色の `#001` | オブジェクトへの参照（説明用の識別子で、メモリアドレスではない） |
| 緑の枠のカード | オブジェクト。関数の中で `new` したものは明るい緑 |
| 水色の実線の矢印（矢じり付き） | 参照型の変数 → オブジェクト |
| オレンジの破線の札と破線（先端は丸） | `ref` 引数。値を持たず、呼び出し元の変数そのものに接続している |
| 黄色 | 変更された値 |
| 薄く表示されたオブジェクト | どの変数からも参照されなくなったオブジェクト |

演出は操作の種類ごとに 1 つに決めています。

- **コピー（値渡し）**: 送り元の箱が白く光り、中身の札が弧を描いて新しい箱へ飛ぶ。値型でも参照型でも同じ動き。
- **代入**: 札がコードやオブジェクトから飛んで箱に入る。`ref` 引数への代入は、札がオレンジの接続をたどって呼び出し元の箱に入る。
- **メンバーの変更**: 数値の札が変数 → 矢印 → オブジェクトとたどってフィールドに入る。途中の変数の中身は変わらない。
- **参照の付け替え**: 矢印の先端が古いオブジェクトから新しいオブジェクトへ振り向く。

## 使用技術

- 素の HTML / CSS / JavaScript と Canvas 2D。外部ライブラリなし、オフラインで動作。
- 隣の `btree-rtree/` と同じ描画・ナビゲーションの仕組みを使っています。

## 実装の概要

### 状態モデル（`model.js`）

- 変数・値・参照・オブジェクト・関数呼び出しを持つ小さなモデルです。汎用のインタープリターではなく、この発表に必要な操作だけを持ちます。

  | 操作 | 意味 |
  |---|---|
  | `decl` / `new` | 変数の宣言 / オブジェクトの生成 |
  | `set` | 変数への代入（`ref` 引数なら呼び出し元の変数へ） |
  | `copy` | 値渡し。新しい引数変数を作り、中身を複製する |
  | `bind` | 参照渡し。呼び出し元の変数を指す別名（alias）を作る |
  | `field` | メンバーの変更。参照型ならオブジェクトを、struct なら変数の中身を変える |
  | `enter` / `ret` | 関数に入る / 戻る（引数変数が消える） |
  | `print` | `Console.WriteLine(a.Value)` |
  | `init` / `reset` | 初期状態をまとめて作る（シーン7で操作 A と B を独立させるため） |

- 各シーンの C# は操作列として定義します。`compile()` が操作ごとの「前の状態・後の状態・開始時刻・長さ」を先に計算します。
- シーン7の 4 パターンは `patternDef()` で定義し、画面表示と検証の両方で同じ定義を使います。

### 描画（`index.html`）

- 画面は「ステップ番号 `k` と、そのステップに入ってからの経過時間 `t`」だけから毎フレーム描き直しています。
  いま実行中の操作の (前の状態, 後の状態, 進捗 `u`) から表示を作るので、アニメーションの途中状態を変数に持ちません。
  どのステップへ移動しても表示は同じになります。前に進むときは `t = 0` から、戻るときは `t = ∞`（完了状態）で描きます。
- `animate()` は操作の種類ごとに演出を 1 つだけ持ちます。そのため、同じ操作はシーンが変わっても必ず同じ動きになります。
- 比較画面（シーン3・5・6・7）は、本編と同じプログラム定義を縮小レイアウトで同時に再生しています。
- 呼び出し元（左）・オブジェクト（中央）・関数（右）の位置は全シーンで固定しています。

### 検証

4 パターンの結果（関数から戻った後に呼び出し元から見える `a.Value`）は次のコマンドで確認できます。

```sh
node -e 'console.table(require("./model.js").verifyPatterns())'
```

| パターン | 操作A `box.Value = 20;` | 操作B `box = new …{ Value = 30 };` |
|---|---|---|
| 値型 × 値渡し | 10 | 10 |
| 値型 × 参照渡し | 20 | 30 |
| 参照型 × 値渡し | 20 | 10 |
| 参照型 × 参照渡し | 20 | 30 |

シーン7の「呼び出し元の a.Value → …」は、手書きではなくモデルの状態から読み出して表示しています。

## 技術的な注意（発表で聞かれたとき用）

- 「値型はスタック、参照型はヒープ」という説明はしていません。値型の変数でもクラスのフィールドならヒープ上にありますし、JIT の最適化で配置が変わることもあります。この発表の箱と矢印は、意味論を理解するための概念モデルです。
- `#001` は説明用のオブジェクト識別子です。実際のメモリアドレスではありません。
- 参照型の「参照」と、`ref` による参照渡しは別の概念です。図では矢印（水色・実線・矢じり）と接続（オレンジ・破線・丸）で描き分けています。
- 参照されなくなったオブジェクトは薄く表示していますが、いつ回収されるか（GC）はこの発表では扱いません。
- 変更可能な struct（`public int Value;`）は説明用です。実務では struct を不変にすることが推奨されます。
- `in` / `out` 引数や `ref readonly`、`record struct` などは扱っていません。
