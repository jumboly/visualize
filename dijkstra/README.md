# ダイクストラ法を可視化して腹に落とす

「最短経路探索は、ゴールを目指して道を探すこと」という先入観を壊し、ダイクストラ法が
**出発地点からの累積コストが小さい順に、波紋のように最短コストを確定させていく**様子を
アニメーションで理解するためのインタラクティブ教材です。社内のゆるトーク（6章・約30分）で使います。

| 章 | タイトル | 中心となるメンタルモデル |
|---|---|---|
| 1 | 最短経路探索はゴールを目指さない | 波紋のように、累積コストの小さい順に探索が広がる |
| 2 | 1対1も1対Nも同じ | 目的地は探索の方向を決めない。決めるのは「いつ止めるか」だけ |
| 3 | 道路ネットワークの世界 | 最短経路は、道路のコストと通行可能性で決まる |
| 4 | 波紋から商圏を作る | 最短コストの探索結果を、面の情報に変換する |
| 5 | 階層探索で高速化する | アルゴリズムだけでなく、探索する対象の構造を工夫する |
| 6 | 巡回セールスマン問題 | ダイクストラ法の結果を、別の最適化問題の入力にする |

発表の進め方は [script.md](script.md)（各章5分のデモ進行台本）にあります。

## 開き方

- **ビルド済み**：`dist/index.html` をブラウザ（Chrome / Edge / Safari の最新版）で開くだけで動きます。
  JS と CSS をすべて埋め込んだ1ファイルなので、サーバーもネットワークも要りません。
- **開発**：Node.js 20 以上で

```sh
npm install
npm run dev        # 開発サーバー（http://localhost:5173）
npm test           # 自動テスト（Vitest）
npm run typecheck  # 型チェック
npm run build      # 型チェック + dist/index.html の生成
```

`dist/index.html` はリポジトリにコミットしています（他のスライドと同じく、直接開けるようにするため）。
ソースを変更したら `npm run build` で作り直してください。

### 設計の要点

- **通行条件はグラフを作る側の責任**：`buildSearchGraph(network, {mode, metric, closed, slow})` が、
  一方通行・道幅（大型車は 5.5m 未満不可）・歩行者専用・通行止め・渋滞を「エッジがあるか・コストはいくつか」に変換します。
  ダイクストラ法は道路の意味を知りません（第3章「ダイクストラ法から見える世界」でそのまま表示）。
- **計算と描画の分離**：ダイクストラ法は `init / settle / relax / done` のイベント列を記録し、描画はそれを
  時刻 t で再生するだけです。t を戻せば前の状態を作り直せるので、一時停止・巻き戻し・スクラブが同じ仕組みで動きます。
- **2種類のタイムライン**：「1手ずつ」（イベントごとに一定時間）と「波紋」（時刻＝累積コスト）。
  波紋モードでは、確定済みノード u から出るエッジを `(半径 − u の最短コスト) / エッジのコスト` の割合まで塗るので、
  塗られた範囲は「出発地点からその累積コスト以内で届く道路区間」そのものです（見た目のために不正確な表現をしていません）。
- **同点の扱い**：優先度付きキューは同じコストならノード番号の小さい順に取り出すので、毎回同じイベント列になります。

## データ（架空の街）

2.4km × 1.5km。100m 間隔の格子を基本に、固定シードでゆがめています。

- 南北に川。橋は **北大橋**（幹線）、**旧橋**（幅 4m・東向き一方通行）、**歩道橋**（歩行者専用）、高速道路の高架の4本
- 東西に線路。道路が渡れるのは4か所の踏切だけ
- 北西：碁盤目と一方通行 / 南西：狭い路地の旧市街（大型車は通れない） / 北東：公園の遊歩道 / 南東：行き止まりの多い住宅地
- 速度（km/h）：徒歩 4.8、普通車は高速 60・ランプ 30・幹線 40・一般道 25・狭い道 12、大型車は 50・25・30・20・10

## 正確性（テスト）

`npm test` で次を確認しています（60 件）。

- ダイクストラ法：ランダムな有向グラフで Bellman-Ford と一致、経路復元、到達不能、一方通行、
  暫定コストの更新（単調減少・最後の更新値が確定値）、確定コストの単調性と確定済みノードが更新されないこと
- 1対N：個別の1対1と一致、確定順が1対1・1対N・1対全点で共通、到達不能な目的地
- 通行条件：一方通行（歩行者は両方向）、通行止め、大型車の道幅、距離／時間・渋滞、第3章の各例の前提
- 到達圏：道路途中の到達限界（9分 + 3分の道 → 1/3 地点）、全点探索との一致、反転グラフによる方向の違い、
  メッシュ化（細かい標本点と突き合わせ）
- 階層探索：ランダムグラフ×ランダム分割、道路網の 1,000 組で通常のダイクストラ法と最短コストが一致、
  同じ領域内の経路、領域を出て戻る経路、往路と復路、経路展開の連続性
- OD マトリックス・TSP：各セルが1対1と一致、行と列の向き、非対称、全列挙と Held-Karp の一致、
  巡回コストと OD マトリックスの一致、道路上への経路復元

## 発表で聞かれたとき用の注意

- 「波紋」は比喩です。広がる基準は直線距離ではなく、道路に沿った累積コストです。
- ダイクストラ法がいつも最適な選択というわけではありません。目的地の情報を使う A* などもあります。
- メッシュ商圏は「到達できる道路と交差するセル」を塗る近似です。街区の内側（道路のないセル）は塗られず、
  セルの大きさで面積が変わります。
- 第5章の階層探索は、領域分割と上位ノードを使う方式の一例です（Contraction Hierarchies そのものではありません）。
  この小さな街では、確定ノード数は減っても実測時間はほとんど変わらず、逆転することもあります。
  画面の実測時間はブラウザでその場で測った値で、前処理のコストは別に表示しています。
- 第6章の TSP は、小さな問題なので全列挙で厳密解を求めています（検算に Held-Karp 動的計画法）。
  地点が増えると (n−1)! 通りに爆発するため、実務では別の解法を使います。
