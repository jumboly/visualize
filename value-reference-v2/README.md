# 値渡しなのに値が変わる？（v2）

値型・参照型と値渡し・参照渡しを、箱と矢印のアニメーションで見せる5分発表（ゆるトーク）用の HTML プレゼンテーションです。
4パターンを暗記させるのではなく、次の3つの原理から結果を導けるようになることを目指しています。

1. 変数には何が入っている？
2. コピーする？ 元の変数を操作する？
3. 変数を変える？ オブジェクトを変える？

## 起動方法

- `index.html` をブラウザ（Chrome / Edge / Safari / Firefox の最新版）で開くだけで動きます。ビルド・サーバー・ネットワーク接続は不要です。
- `F` キーか右下の ⛶ ボタンでフルスクリーンになります。
- 画面は 1920×1080（16:9）で描画し、ウィンドウに合わせて拡大・縮小します。比率が違う画面では上下または左右に余白が出ます。
- URL の `#番号` が現在のステップです（例: `index.html#14`）。リロードしても同じステップから再開できます。

## 操作方法

| 操作 | 動作 |

| → / Space / Enter / PageDown | 次のステップ |
| ← / Backspace / PageUp | 前のステップ |
| Home / End | 最初 / 最後のステップ |

- 演出の途中で操作しても、連打しても表示は崩れません。
- マウスを 2.5 秒動かさないとカーソルが消えます。

## 見た目のルール

同じ操作には、どのシーンでも同じ演出を使っています。

| 要素・操作 | 表現 |
|---|---|
| 変数 | 青い枠の箱（左上に変数名と型） |
| 値 | 白い数字。構造体（`ValueBox`）は「Value = 10」が箱の中に直接入る |
| 参照 | 水色の `#001`。説明用の識別子で、メモリアドレスではない |
| オブジェクト | 緑のカード（型名と `#001`）。新しく作られたものは明るい緑 |
| 変数 → オブジェクト | 水色の実線の矢印（変数の箱の横から出て、カードを指す） |
| `ref` による接続 | オレンジの破線＋「ref」ラベル。引数は箱ではなくオレンジの名札（「a の別名」）で、線は呼び出し元の**変数の箱の上辺**に刺さる。オブジェクトには向かわない |
| 変更された値 | 黄色 |
| A. 値のコピー | 元の箱の中身の複製が弧を描いて新しい箱へ飛ぶ（元はそのまま） |
| B. 共有 | 2 本の矢印を同時に光がたどり、同じカードに着く |
| C. オブジェクトの状態変更 | 黄色い光が変数 →（矢印）→ カードの Value まで進み、値がめくれる。変数の中身は変わらない |
| D. 変数への代入 | 新しい中身が箱に入り、古い中身ははじき出される。参照なら矢印が新しい相手へ振れる。ref 経由ならオレンジの線を通って呼び出し元の箱まで届く |
| 関数呼び出し | 紫の破線の枠。`return` 後は薄くなり「終了」と表示 |

## 使用技術

- 素の HTML / CSS / JavaScript のみ。外部ライブラリ・Web フォントなし（オフラインで動作）。
- 箱やカードは HTML 要素、矢印と ref の線は SVG、動きは Web Animations API です。
- `model.js` は `<script>` で読み込んでおり、ES Modules は使っていません（`file://` で直接開けるようにするため）。

## 実装の概要

### 状態モデル（`model.js`）

C# の動きを、変数・値（int / 構造体 / 参照）・オブジェクト・関数の枠・`ref` の別名だけで表す小さな意味論で実行します。
操作は `declare`（変数）・`newObj`（オブジェクト生成）・`copy`（値渡し）・`refParam`（参照渡し）・`assign`（代入）・`setMember`（メンバー変更）・`print`（Console.WriteLine）です。
`ref` 引数は中身を持たず `alias` で呼び出し元の変数を指すだけなので、代入やメンバー変更は自動的に呼び出し元の変数に届きます。

シナリオ（`build()`）はこれらの操作を 1 ステップずつ実行し、ステップごとに次の 2 つを記録します。

- **スナップショット**：そのステップを実行し終えた状態（変数・中身・オブジェクト・枠・矢印・コード行・説明文など）のすべて
- **イベント列**：そのステップに入るときに起きた操作（`copy`・`assign`・`member` など。並列実行は `par`）

画面に出る a.Value などの結果は、すべてこのモデルが計算した値です。

### 描画と演出（`index.html`）

1. ステップを移動するたびに、動いている演出をすべて止める
2. 移動先のスナップショットを、キー付きの差分更新でそのまま DOM にする（この時点で最終状態が完成）
3. ちょうど 1 ステップ進んだときだけ、イベント列を演出として再生する

演出は「最終状態の上に重ねる飾り」です。到着前の値は一時的に隠し、飛んでいく値は一時要素で描きます。止めれば一時要素が消えて最終状態が見えるだけなので、連打や途中の操作で状態が壊れません。
演出の出発点・到着点は、描画直後に測った実際の位置から取っています。

### 検証（`verify/`）

画面に表示している C# コードを `model.js` から取り出してコンパイル・実行し、出力がモデルの結果（＝画面の値）と一致するかを確かめます。

```sh
node verify/check.js    # .NET SDK が必要（net8.0 以降。Verify.csproj の TargetFramework を手元に合わせる）
```

現在の結果（全 15 ケース一致）：

| パターン | 操作A：`box.Value = 20` | 操作B：`box = new … { Value = 30 }` |
|---|---|---|
| 値型 × 値渡し | 10 | 10 |
| 値型 × 参照渡し | 20 | 30 |
| 参照型 × 値渡し | 20 | 10 |
| 参照型 × 参照渡し | 20 | 30 |

## 技術的な注意（発表で聞かれたとき用）

- 図は意味論を説明するための概念モデルです。スタック・ヒープ・GC・JIT 最適化などの実装は扱っていません。「値型はスタック、参照型はヒープ」とは限りません（参照型のフィールドにある値型はヒープに置かれる、など）。
- `#001` はオブジェクトを区別するための説明用の名前で、実際のアドレスではありません。C# の参照は、実装上アドレスであることもありますが、言語仕様としては不透明な値です。
- C# の `ref` 引数は、呼び出し元の変数（格納場所）への別名です。参照型の「オブジェクトへの参照」とは別の概念なので、図でも線の色・形・つながる先を分けています。
- C# の引数は `ref` / `out` / `in` を付けない限り値渡しです。参照型でも「参照の値」がコピーされます。
- シーン7の `struct ValueBox { public int Value; }` は説明のための変更可能な構造体です。実務では構造体は不変（`readonly struct`）にするのが一般的です。
- シーン1〜6 は依頼のシナリオどおり `int` と `class Box` を使い、シーン7で `ValueBox` / `ReferenceBox` を使っています。
- コードは「関数」「呼び出し元」「型」のブロックに分けて表示しています。トップレベルステートメントの 1 ファイルにする場合は、型の宣言をファイルの末尾に置きます。
